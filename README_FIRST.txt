JIRA SURVEY STATUS AUTOMATION - VERSION 2.1
Developed by Perry Dave V. Geron

OVERVIEW
========
Version 2 retains incremental refresh and adds dedicated comment fields.
The Excel Ribbon has TWO commands:
  1. Generate Survey Status - create a new report from a JIRA export.
  2. Update Survey Status   - update a saved existing report using a new export.

The tool runs locally using Microsoft Excel desktop for Windows. The ZIP
contains commented VBA source and a PowerShell installer which uses your
local Excel installation to build a genuine .XLAM add-in. It does NOT
contain a precompiled, Windows-tested XLAM.

INSTALLATION
============
1. Close all Excel windows. If permitted by your company, unblock the ZIP
   under Windows Properties before extracting it.
2. Extract the entire ZIP to a local folder.
3. If your Excel security configuration permits it, temporarily enable
   File > Options > Trust Center > Trust Center Settings > Macro Settings >
   Trust access to the VBA project object model. Close Excel again.
4. Run Install_JIRA_Survey_Status.cmd from the extracted folder.
5. Reopen Excel. Look for the Survey Status Ribbon with BOTH buttons.
6. After installation, disable programmatic VBA project access again.

The installer saves the previous installed XLAM, if any, to
%APPDATA%\Microsoft\AddIns\JIRA Survey Status Automation_previous.xlam
before replacing it with v2.1. If your company blocks Excel macros, get IT
approval; do not bypass company policy.

FIRST-TIME REPORT (GENERATE)
============================
1. Open the downloaded JIRA CSV or Excel export in Excel.
2. Select Survey Status > Generate Survey Status.
3. A NEW workbook is created; save it as XLSX in your working folder.
4. The report includes HL Comment (column I) and DM Comment (column J)
   immediately after Ticket Status (column H). Both are editable; save
   your notes there. Created follows in column K.
5. The original JIRA export is not modified.

INCREMENTAL REFRESH (UPDATE)
============================
1. OPEN YOUR EXISTING, SAVED Survey Status report (.xlsx) in Excel.
   The status report, NOT the JIRA CSV, must be the active workbook.
2. Select Survey Status > Update Survey Status.
3. When prompted, select the NEW JIRA CSV/XLSX/XLS export.
4. The automation validates Issue Keys and creates a full backup in the SAME
   folder as your report (filename includes _backup_YYYYMMDD_HHMMSS).
5. It updates changed JIRA fields, recalculates date-based statuses, and
   appends previously unseen Issue Keys. The workbook is saved in place.
6. Manually entered data in stakeholder-maintained columns is preserved.
7. Check the new Latest Export Match column; tickets not included in the
   new file remain in the report, flagged Not in Latest Export.

IMPORTANT: JIRA-managed fields such as Pending Issue Remarks and Issue
Resolution Remarks are refreshed from the source export. Put manual notes
in HL Comment, DM Comment (or other custom columns), not those JIRA fields.
If you have previously typed your own notes directly into a JIRA-managed
remarks column, move them to HL Comment BEFORE your first update.

SAFETY AND COMPATIBILITY
========================
- Issue Key is the only ticket matching key (not row number or Company Name).
- Duplicate or blank Issue Keys cause refresh to stop WITHOUT modifying the
  report. The original report and export are never silently deduplicated.
- All stakeholder-owned extra columns remain unchanged. The full-width sort
  keeps each row's notes with its ticket. The system refreshes JIRA fields.
- If the export omits a ticket (e.g., filtered JIRA export), that row remains
  with its previous status and data, marked Not in Latest Export.
- When JIRA creates new columns, they are added to the RIGHT of the existing
  report, without shifting or overwriting existing user columns.
- Reports generated by v2 have a VeryHidden _JSS_Metadata sheet that lists
  JIRA-owned fields. Earlier v1 report versions can be updated; on their
  FIRST update, extra JIRA fields with matching new-export headers are
  treated as managed, except standard stakeholder note column names.
- Existing filters are rebuilt to include appended rows. Current filter
  criteria may be cleared; all rows are preserved.
- Original status sorting by complete Summary A-Z is maintained.
- Raw DD/MM/YYYY CSV parsing remains authoritative. If raw CSV access fails,
  Generate can warn and fall back, but UPDATE refuses to apply potentially
  ambiguous dates. Download the raw CSV to a normal local folder.
- The automation makes a backup before updating; a backup requires the
  workbook folder to be writable and accessible from desktop Excel.
- If the update errors AFTER starting to change the report, DO NOT SAVE the
  partially updated open workbook. Close WITHOUT SAVING and reopen the
  original/backup indicated in the error message.

UNCHANGED APPROVED BUSINESS RULES
=================================
Status priority:
  Approved > RVQ Available > VQ Released > Initial VQ > Not yet started
RVQ tracking for VQ Released tickets without returned RVQ:
  Monday-Friday starting day after VQ release; 0-14 = Within 14 Business
  Days; 15+ = No RVQ Overdue. No holiday calendar or analyst SLA metrics.
Pending Issue Indicator and Issue Resolution Status are separate; no
remarks-based workflow inference. For Approved / VQ Released they are N/A.
Dates display MMM DD but keep actual Excel date/year. No source export is
modified. Issue Key is a clickable hyperlink to:
  https://jira.ehr.com/browse/<Issue Key>

V2 UPDATE METRICS
=================
At the top of the report, the add-in updates stage totals and counts for
New Tickets, Updated Tickets, Unchanged Tickets and Not in Export, plus
Last Updated and execution Runtime. It also keeps the report date.

VERSION 2.1 - HEADER AND COMMENT LAYOUT
=======================================
- Column H: Ticket Status (formerly Survey Status).
- Column I: HL Comment (formerly Stakeholder Remarks).
- Column J: DM Comment (new stakeholder-owned column).
- Column K: Created; all subsequent date/status columns shift right by two.
- Both comment columns are preserved during Update Survey Status, never
  overwritten from JIRA. They remain attached to each ticket's Issue Key.
- On the first v2.1 update of an existing v2.0 workbook, the previous
  Stakeholder Remarks is renamed/moved to HL Comment without losing its notes,
  and DM Comment is inserted as a new blank field. A backup is made first.
- If the workbook already contains both HL Comment and Stakeholder Remarks,
  both are preserved; Stakeholder Remarks remains as an additional manual
  column to avoid losing any data.
- The update migrates only table rows, leaving the report KPI summary intact.

A fictional layout preview is included at examples/JIRA_Survey_Status_v2.1_Illustrative_Layout.xlsx.
The preview is illustrative only; VBA calculations must be verified in Windows Excel.
